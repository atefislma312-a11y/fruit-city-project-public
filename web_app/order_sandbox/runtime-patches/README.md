# Development cashier integration — 2026-10-26

The existing local development server at development/pos_inventory_repair/server.js was edited in place. Its directory is pre-existing and untracked, so this repository stores only the reviewed incremental patch rather than uploading its unrelated files, caches, or databases. The patch depends on that server's existing durable-commit.mjs import and saveDatabaseAtomic implementation; it is not a standalone cashier distribution. It was verified with git apply --reverse --check against the edited server. Do not apply it blindly to another version.

Changes: restore the pre-write SQL.js snapshot on failed persistence for both runSql and runTransaction; forbid asynchronous transaction callbacks; await owner setup and ingredient update transactions before success responses. Existing synchronous business callbacks are preserved. Added an opt-in pull worker inside the cashier process using that same queue, without opening a second database writer.

The opt-in uses FC_DEV_ORDER_BRIDGE_URL (HTTP 127.0.0.1 only), FC_DEV_BRIDGE_TOKEN, FC_DEV_BRANCH_ID, FRUIT_CITY_DEV_PORT and FRUIT_CITY_DEV_DB_PATH. The database must be a .test.db beneath the development server directory. Configuration validation occurs before startup recovery or DB initialization. Do not point it at a real cashier database. No InstaPay fee rule is fabricated. The worker catches delivery failures, backs off and leaves durable source events pending until ACK. Closing its worker drains the current poll; the existing server process signal handling still exits immediately and should be qualified before operational use.

Verification: runtime-writer.test.mjs executes the actual development server's database-function section in an isolated VM, using real SQL.js and a synthetic database. It does not import the HTTP listener. Confirmed disk failure leaves memory/disk/stock unchanged, single-statement write recovery, retry, file reopen and lost ACK deduct once. pos-worker.test.mjs tests real loopback HTTP polling with a failing writer and retry. Full suite: 48 passed, zero skipped with FC_SQLJS_MODULE and FC_POS_RUNTIME set. node --check passes for the modified server.

Still unverified: launching the complete development cashier server, cashier UI integration, shutdown/recovery across the entire runtime, and its API authentication. Inspection found existing cashier API routes without a general authentication gate; keep it local and do not expose it or connect real orders until that is repaired. The new polling hook is implemented but not enabled. Public website and production cashier unchanged. Remaining product gates include RF/weight identities, delivery zone geometry, production identity/retention/backups and release approval.
